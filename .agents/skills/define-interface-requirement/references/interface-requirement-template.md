- 使用业务名称，不把未确认数据库字段写成产品要求。

## 四类协作场景补充检查

### 我方主动推送

- 哪个业务事件触发推送？
- 对方是否需要回执，回执代表接收还是处理完成？
- 对方不可用时是否阻塞我方主流程？
- 推送失败由谁重试、补偿和告警？
- 重复推送是否会造成重复业务结果？
- 对方处理成功但回执丢失时如何判断？

### 对方主动获取

- 对方在什么场景和频率下调用？
- 对方需要哪些查询条件和数据范围？
- 分页、全量访问、大数据量和高频访问有什么业务限制？
- 数据不存在、无权限或已经失效时返回什么业务结果？
- 是否允许获取历史数据和敏感数据？
- 对方使用数据后产生的问题由谁负责？

### 我方被动接收

- 对方在哪个业务节点推送？
- 我方如何识别业务唯一对象和重复数据？
- 对方提供的数据是否足以完成下一业务步骤？
- 校验失败如何反馈，对方是否需要修正重推？
- 我方接收成功和业务处理成功是否需要区分？
- 对方撤回、更正或重放数据时如何处理？

### 我方主动获取

- 用户操作、业务事件还是定时任务触发？
- 用户是否必须等待，超时后页面和状态如何处理？
- 需要实时查询还是可使用缓存或本地数据？
- 对方数据不存在、延迟或错误时如何降级？
- 获取成功但本地保存失败时如何恢复？
- 对方接口变更、限流或配额不足时如何处理？
