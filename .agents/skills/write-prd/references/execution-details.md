# 执行细则与检查表

> 本文件供 `write-prd` Skill 第 10 步"补齐执行细则"调用。按需求类型和风险维度组织，不要求机械输出全部章节。

---

## 一、按需求类型读取

### 需求变更说明

仅读取与变更直接相关的部分：

- **页面与交互**：变更涉及的页面、组件、状态和文案；不影响的部分明确声明。
- **业务规则**：修改前 / 修改后的规则对比；确认旧规则是否仍然生效。
- **数据与字段**：新增/修改/废弃的字段；历史数据是否需要迁移或兼容处理。
- **异常边界**：变更是否引入新的异常场景或改变已有异常的处理方式。
- **验收标准**：变更的最小验收范围（回归 + 新增）。
- **影响范围**：受影响的设计稿、接口、埋点、测试用例、运营配置和用户指引。

### 轻量 PRD

至少覆盖：

- **页面交互**：每个页面的加载、空、成功、失败、禁用和无权限状态。
- **关键业务规则**：影响流程闭环的核心规则（进入/退出条件、触发事件、核心计算）。
- **异常边界**：主要异常场景（网络失败、空数据、重复操作、权限不足）。
- **验收标准**：核心路径的正常、异常和边界验收。

以下部分按需加入：

- 跨系统协作（若涉及第三方或独立系统）。
- AI 或算法能力（若为核心功能机制）。
- 上线迁移要求（若涉及历史数据或用户）。

### 完整 PRD

按适用性读取以下全部章节，跳过与当前产品无关的内容。

## 二、页面与交互细则

| 检查项 | 说明 |
|--------|------|
| 信息层级 | 用户在页面上的视觉动线和信息优先级 |
| 加载状态 | 骨架屏 / loading 动画 / 进度条 |
| 空状态 | 无数据时的占位图、文案和引导操作 |
| 成功状态 | 操作成功后的反馈方式（toast / 页面跳转 / 状态更新） |
| 失败状态 | 错误提示的文案、位置、持续时间和后续操作指引 |
| 禁用状态 | 按钮/控件的禁用条件、禁用样式和 hover/tap 反馈 |
| 无权限状态 | 无权限时的展示（隐藏 / 置灰 + 提示 / 跳转） |
| 输入校验 | 格式、长度、范围、必填、唯一性；前端实时校验 + 后端兜底 |
| 防重复提交 | 按钮置灰、loading 状态、后端幂等 |
| 逆向操作 | 删除、取消、返回、撤销的确认机制和结果反馈 |
| 中断恢复 | 页面关闭、切换、网络中断后返回时的状态保留 |
| 弱网/断网 | 超时时间、重试机制、离线提示 |
| 多端兼容 | 不同屏幕尺寸、系统版本的关键差异说明 |
| 文案规范 | 按钮文案、错误提示、空状态引导语的统一调性 |

---

## 三、业务规则与数据细则

| 检查项 | 说明 |
|--------|------|
| 数据来源 | 每个字段由哪个系统/接口/用户输入产生 |
| 数据去向 | 数据写到哪里，由谁消费 |
| 默认值 | 字段的默认值及适用条件 |
| 空值处理 | null / 空字符串 / 0 的业务含义是否区分 |
| 计算规则 | 公式、精度、四舍五入、单位转换 |
| 时间边界 | 日期/时间的时区、截止时间、周期定义 |
| 状态定义 | 每个状态的进入条件、退出条件、允许操作 |
| 排序/筛选 | 默认排序、筛选条件、搜索范围 |
| 唯一性约束 | 什么条件下不允许重复（如"同一员工+同一日期"） |
| 历史数据 | 旧数据的兼容策略（迁移 / 标记 / 归档 / 忽略） |
| 数据权限 | 行级/列级数据权限，与功能权限的区别 |
| 敏感数据 | 加密存储、脱敏展示、日志脱敏 |

---

## 四、异常与边界细则

| 检查项 | 说明 |
|--------|------|
| 网络异常 | 超时重试次数、退避策略、超时后的用户提示和操作 |
| 并发冲突 | 乐观锁/悲观锁选择、冲突提示和刷新策略 |
| 重复请求 | 幂等键、去重窗口、重复请求的业务语义 |
| 部分成功 | 批量操作中部分失败时的回滚/补偿/提示 |
| 极端值 | 输入边界（最大/最小/0/负值/超长文本）的处理 |
| 跨天/跨时区 | 时间计算以哪个时区为准，跨天数据的归属规则 |
| 降级方案 | 依赖服务不可用时的替代行为 |
| 人工兜底 | 系统无法自动处理时的运营入口 |

---

## 五、跨系统与 AI 细则

| 检查项 | 说明 |
|--------|------|
| 调用方向 | 谁主动发起，触发节点是什么 |
| 时效要求 | 实时/准实时/异步/定时；用户是否需要等待 |
| 失败处理 | 超时/错误/空返回时的业务行为和用户提示 |
| 数据契约 | 字段映射、枚举对齐、状态同步方向 |
| 第三方依赖 | API Key、配额、SLA、降级方案 |
| AI 输入来源 | 数据从哪里获取，质量是否可靠 |
| AI 输出用途 | 输出由谁使用、进入什么下一动作 |
| AI 失败兜底 | 识别/生成失败时的替代方案（人工 / 规则 / 降级提示） |
| AI 人工审核 | 高风险输出是否需要人工确认 |

## 六、上线与迁移细则

| 检查项 | 说明 |
|--------|------|
| 历史数据迁移 | 迁移脚本、校验方式、失败回滚 |
| 新老版本兼容 | 旧版客户端是否仍可使用；新旧数据混合期间的行为 |
| 灰度策略 | 灰度比例、观察指标、放量条件、回滚触发条件 |
| 配置开关 | 功能开关的位置、默认值、紧急关闭流程 |
| 发布顺序 | 前端/后端/配置的发布依赖顺序 |
| 回滚方案 | 回滚步骤、数据回滚范围、回滚后的用户通知 |

## 七、验收标准细则

| 检查项 | 说明 |
|--------|------|
| 正常路径 | 主流程从头到尾每个关键节点的可观察结果 |
| 异常路径 | 每个主要异常场景的系统行为和用户反馈 |
| 边界值 | 输入边界、时间边界、数量边界的验收 |
| 权限验收 | 每种角色的可见性和可操作性 |
| 并发验收 | 多端同时操作、快速重复点击的结果 |
| 回归验收 | 变更影响范围内的原有功能验收 |
| 可观察性 | 是否能用日志/数据库/埋点验证而非仅靠前端表现 |

## 八、运营配置需求

> 当需求依赖后台配置、内容维护或人工运营操作时，按需读取以下检查项。

| 检查项 | 说明 |
|--------|------|
| 配置对象 | 哪些功能依赖后台配置（如菜品库、课程列表、方案参数） |
| 配置频率 | 每次更新的典型频率（每日/每周/按需） |
| 配置责任人 | 谁负责配置和维护（如菜单管理员、内容运营） |
| 冷启动策略 | 首次上线时初始数据从哪来（导入/手动录入/系统生成） |
| 内容审核 | 用户生成内容或运营发布内容是否需要审核；审核流程 |
| 上下架机制 | 内容或配置的生效/失效/下架条件 |
| 配置校验 | 配置错误时的提示（如"该日期已有菜品发布"） |
| 配置变更通知 | 配置变更后是否需要通知相关方 |
| 运营数据看板 | 运营人员需要查看什么数据来判断效果 |
| 人工兜底入口 | 自动化流程失败时的人工处理入口 |

---

## 九、数据统计需求

> 当需求涉及埋点、指标追踪或数据验证时，按需读取以下检查项。

| 检查项 | 说明 |
|--------|------|
| 核心业务指标 | 本需求要验证的关键行为或结果指标 |
| 指标口径 | 每个指标的计算公式、数据来源、去重逻辑 |
| 埋点事件 | 需要埋点的用户行为事件列表（事件名/触发时机/上报字段） |
| 埋点责任人 | 埋点需求和验证的责任人 |
| 数据看板 | 指标展示位置（后台看板/BI报表/实时大屏） |
| 数据刷新频率 | 实时/准实时/T+1 |
| 数据留存 | 原始数据和聚合数据的保留周期 |
| 异常数据监控 | 什么数据波动需要预警（如"投票数突降50%"） |
| A/B 测试需求 | 是否需要 A/B 测试；变量和对照组定义 |
| 导出需求 | 是否需要数据导出功能；导出字段和格式 |

## 十、非功能需求按模块绑定

> 完整 PRD 中，非功能需求不应作为通用章节一次性列出。每个模块应各自说明：

| 模块 | 性能期望 | 安全约束 | 兼容边界 |
|------|----------|----------|----------|
| F1: XXX | 加载耗时 / 并发量 / 数据量上限 | 该模块特有的敏感数据或权限 | 支持的系统版本、多端差异 |

通用非功能要求（如全站 HTTPS、全局超时时间）仍可单独陈述，但模块特有的性能、安全和兼容要求必须绑定到模块，不能笼统地写"所有页面加载 < 2 秒"。
