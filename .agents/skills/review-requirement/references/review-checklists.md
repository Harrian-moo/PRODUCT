# 需求审查检查表

> 本文件供 `review-requirement` Skill 第 5 步"分维度审查"调用。按审查模式组织，选择对应章节读取。

---

## 一、快速准入检查

适用于评审会前或时间有限的快速筛查。只读取以下 4 组：

### A. 目标与范围

| # | 检查项 |
|---|--------|
| A1 | 目标用户和核心场景是否明确可识别 |
| A2 | 本期范围和明确排除范围是否清晰 |
| A3 | 需求目标是否可验证（而非"完成开发""上线功能"） |
| A4 | 是否存在目标与范围明显冲突（如目标需要 A 但范围排除了 A） |

### B. 流程与状态

| # | 检查项 |
|---|--------|
| B1 | 核心主流程是否可以走通（从触发到结果无断点） |
| B2 | 关键状态是否定义了进入和退出条件 |
| B3 | 是否存在"状态黑洞"——进去后找不到出路 |
| B4 | 逆向操作（取消/撤销/删除）是否定义了路径 |

### C. 异常与边界

| # | 检查项 |
|---|--------|
| C1 | 网络失败/超时是否有处理策略 |
| C2 | 空数据/无权限/登录过期的行为是否定义 |
| C3 | 重复提交/并发操作是否有防重和幂等机制 |
| C4 | 极端输入（空值/超长/负值/零值）是否有校验 |

### D. 验收与重大风险

| # | 检查项 |
|---|--------|
| D1 | 是否定义了可观察、可重复的验收标准 |
| D2 | 是否存在明显的权限越界（如普通用户可执行管理操作） |
| D3 | 敏感数据（个人隐私/金融/健康）是否有明确的保护措施 |
| D4 | 是否依赖未 Ready 的外部系统或第三方 |

## 二、完整审查

在快速准入基础上，补充读取以下章节。

### E. 一致性检查

| # | 检查项 |
|---|--------|
| E1 | 同一概念在不同章节的名称是否一致 |
| E2 | 同名词是否指代不同对象 |
| E3 | 规则是否在多处重复定义且内容矛盾 |
| E4 | 流程图、状态表、规则描述是否互相一致 |
| E5 | 字段表中的字段是否在页面描述中都有出现位置 |

### F. 流程完整性

| # | 检查项 |
|---|--------|
| F1 | 每个分支流程的触发条件是否明确 |
| F2 | 中断后能否恢复到可继续状态 |
| F3 | 并发操作（多端/多人同时）的业务结果是否定义 |
| F4 | 是否存在"幽灵步骤"——提到但未在任何流程中定位 |

### G. 权限完整性

| # | 检查项 |
|---|--------|
| G1 | 每种角色是否在权限矩阵中有完整覆盖 |
| G2 | 权限矩阵与页面/接口描述是否一致 |
| G3 | 数据权限和功能权限是否区分清楚 |
| G4 | 权限变更/撤销时的处理是否定义 |

### H. 数据完整性

| # | 检查项 |
|---|--------|
| H1 | 每个字段是否有来源和去向 |
| H2 | 默认值、空值、异常值的业务含义是否无歧义 |
| H3 | 计算规则是否包含边界情况（除零、精度、四舍五入） |
| H4 | 时间边界是否明确定义（时区、跨天、截止时间） |
| H5 | 历史数据/旧版本数据的兼容策略是否说明 |

### I. 接口与跨系统

| # | 检查项 |
|---|--------|
| I1 | 接口的提供方、使用方和责任系统是否明确 |
| I2 | 超时/失败/重试的业务行为是否定义 |
| I3 | 双方字段、枚举、状态是否同步且语义一致 |
| I4 | 数据同步方向和时效是否定义 |

### J. AI 与内容

| # | 检查项 |
|---|--------|
| J1 | AI 输入的数据来源是否可靠 |
| J2 | AI 输出的使用者和后续动作是否明确 |
| J3 | AI 失败/不确定时的兜底方案是否定义 |
| J4 | 内容审核/更新/下架的责任人是否明确 |
| J5 | 冷启动（无历史数据）时的行为是否定义 |

### K. 非功能需求

| # | 检查项 |
|---|--------|
| K1 | 是否有性能要求或已知的性能瓶颈 |
| K2 | 隐私/合规要求是否覆盖 |
| K3 | 可观测性（日志/监控/告警）是否覆盖关键节点 |
| K4 | 兼容性要求（系统版本、多端）是否说明 |

### L. 上线与发布

| # | 检查项 |
|---|--------|
| L1 | 是否有灰度/发布策略 |
| L2 | 回滚条件和步骤是否定义 |
| L3 | 历史数据迁移方案是否完整 |
| L4 | 埋点和监控指标是否定义 |

## 三、变更影响审查

| # | 检查项 |
|---|--------|
| V1 | 修改前后差异是否明确记录 |
| V2 | 变更影响的页面/流程/规则/数据/接口是否全部识别 |
| V3 | 历史数据和旧版本是否兼容 |
| V4 | 埋点和统计口径是否需要同步调整 |
| V5 | 设计稿/测试用例/运营配置/用户指引是否需要同步更新 |
| V6 | 回归测试范围是否覆盖变更影响面 |
| V7 | 是否有对下游系统或第三方的破坏性变更 |

---

## 四、专项审查

按用户指定维度，从以上章节中选取对应 A-L 编号的检查项，只输出专项结论。

例如：
- 权限专项：G1-G4 + A4 + D2
- 异常专项：C1-C4 + F2-F3 + I2
- 接口专项：I1-I4 + E5 + V6-V7
- 数据专项：H1-H5 + E5 + V3-V4
- AI 专项：J1-J5 + I2 + D4

---

> 检查表用于发现问题，不是必须逐条补齐的模板。跳过不适用项，不生成空泛意见。
